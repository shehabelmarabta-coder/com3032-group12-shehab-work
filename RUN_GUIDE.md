# Run Guide for the Marker — Group 12 (COM3032 / COMM074)

This file orients the marker. The full report sits in `reports/`; this guide describes how to reproduce every result in the repository.

## Environment

Python 3.11+ (tested on 3.14 with the versions pinned in `requirements.txt`):

```bash
pip install -r requirements.txt
```

Key packages: `xgboost>=2.0`, `shap>=0.43`, `imbalanced-learn>=0.11`, `scikit-learn>=1.3`.

## Data

Place the raw Pozzolo CSV at `data/raw/creditcard.csv` (also committed to the repository for convenience). Source: `mlg-ulb/creditcardfraud` on Kaggle, Dal Pozzolo et al. 2015.

The processed CSVs in `data/processed/` were generated by `notebooks/group/01_Group_Preprocessing.ipynb` and are stratified 70 / 15 / 15 splits with `random_state = 42`. They contain 28 PCA features (`V1`–`V28`), `Amount`, eight engineered features, and the binary target `Class`. Detail in §1 (data dictionary) and §2.

## How to reproduce — order matters

1. **Preprocessing.** Run `notebooks/group/01_Group_Preprocessing.ipynb` top-to-bottom. Regenerates `data/processed/train_processed.csv`, `val_processed.csv`, `test_processed.csv` and the EDA figures in `outputs/figures/group_*.png`.
2. **Individual modelling.** Each member's notebook lives in `notebooks/individual/<name>/`. Each loads the processed CSVs, runs baseline + tuned, three imbalance strategies, threshold tuning on validation, model-appropriate SHAP, and writes `outputs/results/results_<name>.csv` to the locked schema (defined in `src/evaluation.evaluate_model_full`).
3. **Cross-member integration.** Run `notebooks/group/02_Group_Visualisation_Recommendations.ipynb`. Aggregates every `results_*.csv` file into `outputs/results/group_comparison.csv` and produces `outputs/figures/group_pr_auc_comparison.png`, `group_recall_at_90p_comparison.png`, `group_precision_recall_scatter.png`.

The Group Notebook 2 is robust to missing-member CSVs: it ingests legacy 7-column schemas by NaN-padding the missing locked-schema fields and proceeds.

## Locked evaluation schema

Every member writes results to a shared 16-column schema via `src.evaluation.evaluate_model_full`:

```
member, model, split, imbalance_strategy, threshold,
pr_auc, roc_auc, recall_at_90p,
f1, precision, recall, accuracy,
tp, fp, fn, tn
```

PR-AUC is the locked primary metric (appropriate for the 0.167 % class prior). `recall_at_90p` is the locked secondary metric (recall at >= 90 % precision). Threshold is the F1-optimal threshold from the validation PR curve, applied to the test set once.

## Known limitations of the submission

1. **Group cross-comparison completeness.** The §4 cross-comparison framework (`notebooks/group/02_Group_Visualisation_Recommendations.ipynb`) ingests every `results_<name>.csv` present at run-time. The numerical breadth of the comparison depends on how many members had pushed their CSV at submission time; the mechanism-led discussion is independent of this.
2. **Enisa's notebook path.** Enisa's KNN + LogReg L1 notebook on `enisa-modelling` is at `individual_notebooks/enisa_knn_logreg.ipynb` rather than the canonical `notebooks/individual/enisa/`. Her results CSV (`outputs/results/results_enisa.csv`) follows the legacy 7-column schema rather than the new 16-column locked schema; the aggregator handles this by NaN-padding the missing fields.
3. **`main` branch state.** The default `main` branch at submission may not yet contain the merged work — the marker should pull `shom-modelling` for the full submission state, or pull each member's `<name>-modelling` branch for their individual work.

## Reproducibility

`random_state = 42` is centralised in `src/config.py` as `RANDOM_STATE` and used in every split, search, and model. Re-running the preprocessing notebook regenerates identical processed CSVs; re-running the individual notebooks produces identical metrics to the values in the committed results CSVs.
